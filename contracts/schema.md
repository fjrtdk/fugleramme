# contracts/schema.md — Fugleramme SQLite Schema Contract

**Version:** v1  
**Engine:** SQLite 3.x  
**Managed by:** `@Data` via migration files in `migrations/`.

All migrations must be reversible. A migration must never be deployed ahead of the code that requires it.

---

## Table: `users`

Stores registered user accounts.

```sql
CREATE TABLE users (
    id               TEXT        NOT NULL PRIMARY KEY,        -- UUID v4, generated by the application
    username         TEXT        NOT NULL,                    -- Display name; unique; derived from email local-part if not supplied
    email            TEXT        NOT NULL UNIQUE,             -- Normalised to lowercase
    password_hash    TEXT        NOT NULL,                    -- bcrypt or argon2id hash; plain-text password never stored
    onboarding_seen  INTEGER     NOT NULL DEFAULT 0,          -- Boolean: 0 = not seen, 1 = seen
    created_at       TEXT        NOT NULL,                    -- ISO 8601 UTC, e.g. '2024-01-01T00:00:00Z'
    updated_at       TEXT        NOT NULL                     -- ISO 8601 UTC; updated on every PATCH
);
```

### Constraints

| Column | Constraint | Notes |
|---|---|---|
| `id` | `PRIMARY KEY`, `NOT NULL` | Application-generated UUID v4 |
| `username` | `NOT NULL`, `UNIQUE` | 1–64 chars; alphanumeric + `-` and `_` |
| `email` | `NOT NULL`, `UNIQUE` | Lowercased before insert/lookup |
| `password_hash` | `NOT NULL` | Never queried; only compared via hash library |
| `onboarding_seen` | `NOT NULL`, `DEFAULT 0` | SQLite stores booleans as integers |
| `created_at` | `NOT NULL` | Set once on insert; never updated |
| `updated_at` | `NOT NULL` | Updated by application on every write |

### Indices

```sql
CREATE UNIQUE INDEX idx_users_email    ON users (email);
CREATE UNIQUE INDEX idx_users_username ON users (username);
```

The `email` index supports O(1) login lookup. The `username` index enforces uniqueness and supports profile lookup.

## Table: `detections`

Stores every bird detection that passed the confidence threshold and was forwarded to a client.

```sql
CREATE TABLE detections (
    id                  TEXT        NOT NULL PRIMARY KEY,     -- UUID v4
    user_id             TEXT        NOT NULL,                 -- FK → users.id
    species_common      TEXT        NOT NULL,                 -- English common name at time of detection
    species_scientific  TEXT        NOT NULL,                 -- Binomial scientific name
    confidence          REAL        NOT NULL,                 -- [0.5, 1.0]
    illustration_path   TEXT,                                 -- Server-relative path, NULL if no illustration exists
    detected_at         TEXT        NOT NULL,                 -- ISO 8601 UTC

    FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
);
```

### Constraints

| Column | Constraint | Notes |
|---|---|---|
| `id` | `PRIMARY KEY`, `NOT NULL` | UUID v4 |
| `user_id` | `NOT NULL`, FK | Cascades on user deletion |
| `species_common` | `NOT NULL` | Snapshot of common name at detection time |
| `species_scientific` | `NOT NULL` | Snapshot of scientific name |
| `confidence` | `NOT NULL` | Must be ≥ 0.5 (enforced by application before insert) |
| `illustration_path` | nullable | NULL when no illustration exists for the species |
| `detected_at` | `NOT NULL` | Set by application at inference time |

### Indices

```sql
CREATE INDEX idx_detections_user_detected ON detections (user_id, detected_at DESC);
```

Supports the paginated `GET /api/v1/detections` query: filters by `user_id`, orders by `detected_at DESC`, and uses the cursor (`detected_at < ?`).

## Table: `species`

Reference data for known species: body-mass data used by the frontend for illustration sizing, and the path to the bundled illustration.

```sql
CREATE TABLE species (
    common_name       TEXT    NOT NULL PRIMARY KEY,           -- English common name; natural key
    scientific_name   TEXT    NOT NULL UNIQUE,                -- Binomial; used for cross-reference
    body_mass_g       REAL,                                   -- Mean adult body mass in grams; NULL if unknown
    illustration_path TEXT                                    -- Server-relative path; NULL if no illustration
);
```

### Constraints

| Column | Constraint | Notes |
|---|---|---|
| `common_name` | `PRIMARY KEY`, `NOT NULL` | Natural key; must be unique across species |
| `scientific_name` | `NOT NULL`, `UNIQUE` | Used for deduplication and cross-reference with BirdNET output |
| `body_mass_g` | nullable | `NULL` when data unavailable; frontend uses a fallback size |
| `illustration_path` | nullable | `NULL` when illustration not yet supplied by `@Content` |

### Indices

```sql
CREATE UNIQUE INDEX idx_species_scientific ON species (scientific_name);
```

Supports O(1) lookup by scientific name when persisting a detection (BirdNET outputs scientific names).

## Table: `user_settings`

Stores per-user display settings. One row per user. Row is created with defaults on first save; if no row exists for a user, the application applies the column defaults listed below.

```sql
CREATE TABLE user_settings (
    user_id          TEXT    NOT NULL PRIMARY KEY,             -- FK → users.id; one row per user
    display_mode     TEXT    NOT NULL DEFAULT 'collage',       -- 'collage' | 'latest_bird' | 'newest_arrival'
    margin_percent   INTEGER NOT NULL DEFAULT 4,               -- 0–20 inclusive
    lookback_window  TEXT    NOT NULL DEFAULT '24h',           -- '15m' | '1h' | '6h' | '24h' | 'all'
    max_species      INTEGER          DEFAULT 40,              -- positive integer or NULL (NULL = show all)
    species_sort     TEXT    NOT NULL DEFAULT 'most_heard',    -- 'most_heard' | 'rarest_window' | 'rarest_all_time'

    FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
);
```

### Constraints

| Column | Constraint | Notes |
|---|---|---|
| `user_id` | `PRIMARY KEY`, `NOT NULL`, FK | One row per user; cascades on user deletion |
| `display_mode` | `NOT NULL`, `DEFAULT 'collage'` | Must be one of the three enum values; validated by application before insert |
| `margin_percent` | `NOT NULL`, `DEFAULT 4` | Application enforces range 0–20; SQLite has no CHECK constraint here |
| `lookback_window` | `NOT NULL`, `DEFAULT '24h'` | Enum enforced by application; also used by Newest Arrival mode for novelty window |
| `max_species` | nullable, `DEFAULT 40` | `NULL` means show all species; `0` is not a valid value |
| `species_sort` | `NOT NULL`, `DEFAULT 'most_heard'` | Applies in Collage mode when detected species count exceeds `max_species` |

### Defaults

When a user has no settings row, the application returns (and behaves as if persisted):

| Field | Default |
|---|---|
| `display_mode` | `'collage'` |
| `margin_percent` | `4` |
| `lookback_window` | `'24h'` |
| `max_species` | `40` |
| `species_sort` | `'most_heard'` |

## Entity Relationships

```
users (1) ─────────────────────────── (N) detections
                    user_id FK

users (1) ─────────────────────────── (1) user_settings
                    user_id FK (UNIQUE via PRIMARY KEY)

detections.species_scientific ──────── (lookup) species.scientific_name
                    (no FK; species row may not exist for all detected species)
```

`detections.species_scientific` is **not** a foreign key into `species` because BirdNET may return species not yet present in the `species` reference table (e.g. migratory visitors not in the initial content set). The application resolves the species row at query time when it exists; it falls back to the snapshot values in `detections` when it does not.

## SQLite Configuration Notes

The following pragmas are required at connection time:

```sql
PRAGMA journal_mode = WAL;       -- Enables concurrent reads during writes
PRAGMA foreign_keys = ON;        -- Enforces FK constraints (off by default in SQLite)
PRAGMA synchronous = NORMAL;     -- Safe performance trade-off with WAL
```

These are applied by the application on every new connection; they are not persisted in the migration files.

## Illustration File-Naming Convention

`@Content` must name illustration files using the lowercased scientific name with spaces replaced by underscores:

```
assets/artwork/{genus}_{species}.png
```

Examples:
- `Turdus merula` → `assets/artwork/turdus_merula.png`
- `Parus major` → `assets/artwork/parus_major.png`

`@Backend` derives `illustration_path` by applying this pattern after inference:

```python
path = f"/assets/artwork/{scientific_name.lower().replace(' ', '_')}.png"
```

If the file does not exist on disk, `illustration_path` is set to `null` in the detection message and the database row.
